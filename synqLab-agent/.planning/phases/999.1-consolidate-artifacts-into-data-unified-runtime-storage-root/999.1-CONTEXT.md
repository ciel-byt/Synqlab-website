# Context: Consolidate artifacts/ into data/

## Background

The project currently has two separate runtime storage roots:

- `artifacts/` — legacy catch-all (trained models, knowledge store, user media, FoldX scratch)
- `data/agent_artifacts/` — Phase 13 agent session artifact system (namespaced, DB-tracked)

This creates confusion and split ownership. Phase 999.1 merges everything under `data/`.

## Locked Decisions

### 1. Directory Structure — flat namespaces under data/

```
data/
  models/                  ← brightness/model.pkl, reranker/model.pkl
  knowledge/               ← store.json
  user_media/              ← avatars/, org_avatars/, team_avatars/
  tools/                   ← FoldX binary (already here)
  training_datasets/       ← CSV data (already here)
  pipelines/               ← pipeline scratch (already here)
  agent_artifacts/         ← agent session outputs (already here)
    bundled/               ← PDB samples (already here)
    sessions/
    folding/
    foldx/
    candidates/
    sandbox/
    brightness_models/
```

`agent_artifacts/` stays as-is — it's the agent-specific subtree. Models, knowledge, and user_media become siblings under `data/`.

### 2. Migration Strategy — big-bang rename

Single plan that replaces every `artifacts/` reference to its new `data/` path in one commit. No backward-compat shims. The `artifacts/` directory and its `.gitkeep` are removed in the same commit.

~40 file references across Python adapters, scripts, configs, docker-compose, Helm charts, and tests.

### 3. Docker & Infrastructure — unified mount

- `docker-compose.yml`: keep fine-grained mounts per subdir for security (not a single `./data:/app/data` blanket)
- `Dockerfile`: update `mkdir` from `/app/artifacts/user_media/avatars` to `/app/data/user_media/avatars`
- `Helm chart`: update `values.yaml` and deployment templates to reference `data/` paths

### 4. Config & Env Vars — SYNQLAB_DATA_ROOT

- New env var: `SYNQLAB_DATA_ROOT` (default: `data/`)
- Subsystems derive paths: `$SYNQLAB_DATA_ROOT/models/`, `$SYNQLAB_DATA_ROOT/knowledge/`, etc.
- Keep `SYNQLAB_ARTIFACT_DIR` as a backward-compat alias that overrides just the agent artifact subtree
- Update `configs/gfp11.yaml` hardcoded paths

### 5. Test Fixtures — straight replacement

~15 test files use mock `artifacts/` paths in assertions. Simple string replacement in the same plan — no test helper abstraction needed.

## Deferred Ideas

- None identified

## Downstream Guidance

- **Researcher:** Enumerate every file referencing `artifacts/` (excluding `agent_artifacts`). Group by subsystem (adapters, scripts, configs, infra, tests).
- **Planner:** Single plan is sufficient. Order: create new dirs → move files → update references → update infra → update tests → remove old `artifacts/` dir.
